---
description: Start round 1 on a new effort (a company, idea, deal, decision, initiative or question) on the active bench. Runs intake and run planning (budget, models, estimate) in chat, waits for the principal's go, then fires the cloud routine or runs the full council here. If the effort already has a round, points you to /council-round.
argument-hint: <effort name> [notes] [standard|deep] — or <bench>/<effort name> to target another bench
---

Start a council round 1 for: $ARGUMENTS

Steps, in order:

1. **Resolve bench and effort.** Read `council.md` for the active bench (a `bench/` prefix in the arguments overrides it). If no bench exists, run `/council-setup`. Derive a short slug for the effort. If `benches/<bench>/efforts/<slug>/ledger.json` or `score-history.json` exists, say a prior round exists and hand off to `/council-round` unless the principal insists on a fresh start (then archive the old effort folder as `<slug>-archived-<date>` first).
2. **Intake.** Read `benches/<bench>/bench.md`, its `context/` folder, then `skills/intake`, and run the round-1 batch in one message. Depth is `deep` unless the arguments say `standard` (`skills/convening`); apply the materials gate and say its result. Register attached documents in `documents/index.md`. Write `brief.md`. Say intake is complete in one line.
3. **Plan the run.** Follow `skills/run-planning`, here in this thread: the dollar ceiling, the phases, tracks and seats, a model per seat with one line of why, the estimate from measured figures, and the one-screen summary of the job and the deliverables. Wait for **Go**. Write the approved `### Model plan` into `brief.md`. Nothing is dispatched or fired before this.
4. **Where to run.** If `council.md` records a cloud routine: commit the effort folder, push, and fire the routine with the payload `round <bench>/<slug>` (append ` standard` for that depth) using the routine-trigger tool (`RemoteTrigger run` with the payload in the body); without one, give the principal the payload to paste into "Run now" and stop. Tell them the result arrives as a pull request and roughly when, and that this thread will check on it. If there is no cloud routine, run here: say it will take a while and the session stays open, then continue.
5. **Run here.** Read `agents/chair.md` and act as the chair for the rest of the round, running the phases the depth profile names under the chair's dispatch rules (each seat on its planned model, at most three per turn, named `p<phase> <seat_id>`, with its search budget): roster and relevance ratings (tell the principal, do not wait), analysts, merge with `scripts/merge_ledger.py`, conflict register, stakeholders, red team, rebuttal (unless the bench says off), answer pass, Evidence Auditor, synthesis per `skills/scoring`, `skills/assessment-output` and `skills/council-ledger`.
6. **Run to completion.** Pause mid-round only when the effort is ambiguous, a supplied document contradicts the round's premise, or the chair's material-pivot test is met (`agents/chair.md`: then ask, with the ways forward as buttons). Batch everything else into "What the council needs from the principal."
7. **Close** per `skills/round-close`: build the dashboard and effort index, write the cost receipt, check for stalls, and send the principal the dashboard, the ledger, the assessment and the receipt (`SendUserFile` where available). Then the score label, the score and one-paragraph verdict, the cost line, and the numbered principal-requests list, Tier 0 first. Then one line: "Answer any of these with /council-round <slug> when you are ready; the council carries the rest forward."
8. **While a cloud round runs.** This thread stays the home thread: when the round's PR lands, fetch the branch and send the dashboard and ledger; if the routine goes quiet with no PR, read its run log and say in plain words what stopped it (`skills/round-close`, stalls). If this thread gets long, offer a swap at the next seam (`skills/thread-swap`).
